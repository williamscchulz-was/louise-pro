## Escopo e adaptações (ao pedido original)

Pedido original citava idb/Playwright/ffmpeg + breakpoints mobile+desktop simétricos.
Adaptado à realidade deste projeto (ver `.claude/agents/conselheiro-fable.md` e `CLAUDE.md`):

- **Sem idb/Playwright/ffmpeg instalados** (e não devem entrar como dependência de prod —
  regra dura do projeto: build só faz JSX→JS). Uso as ferramentas `Claude_Preview` já
  disponíveis no ambiente (browser real via CDP): `preview_snapshot` (árvore de
  acessibilidade), `preview_inspect` (CSS computado pixel-preciso), `preview_eval`
  (medições/timing via JS), `preview_console_logs`/`preview_network`.
- **`preview_screenshot` trava** (timeout 30s): o app conecta no Firestore de PRODUÇÃO
  real (long-polling), então a rede nunca fica "idle" — não é bug do app. Uso
  `inspect`+`snapshot`+`eval` como substituto (na prática mais preciso pra espaçamento/
  cor/timing do que olhar frames).
- **Alvo primário = iPhone 16 Pro/Pro Max PWA standalone** (documentado em CLAUDE.md —
  é a única superfície real de uso). Desktop recebe passada leve (não quebrar/ficar
  ilegível), não o mesmo nível de polish — a app é mobile-only por design.
- **Dados reais em produção**: NÃO vou submeter forms nem iniciar timers durante a
  auditoria (escreveria no Firestore compartilhado da família). Auditoria é
  navegação + inspeção, sem mutação de dados.
- Este NÃO é um retrabalho das 4 auditorias já feitas nesta sessão (perf iPhone,
  design/consistência, usabilidade, qualidade de código + a v11.9.113 6-lentes
  adversarial). Foco aqui: o que ainda falta pro nível "prêmio" — física de movimento,
  profundidade/sombra, cheiro de gradiente genérico de IA, hierarquia em telas densas,
  estados vazios/loading/erro, ritmo tipográfico, contraste WCAG.

## Achados (preenchido durante a auditoria)

### Verificação AO VIVO (browser real, dados medidos — não estimados)

1. **[CONFIRMADO, medido] `T.dim` sub-contraste em texto pequeno.** `rgb(85,90,128)`
   (T.dim) em texto 9-11px (eyebrows "Bottle"/"Diaper"/"Sleep"/"Simeticona", timestamps
   "Jul 3", "33min", "3 FRI") mede **2.32-2.94:1** de contraste contra os fundos do
   cosmos — abaixo do mínimo WCAG AA (4.5:1 pra texto <18px). Medido via
   `getComputedStyle` real no DOM renderizado, não hex do source. É o achado de
   contraste mais forte da auditoria — T.dim provavelmente precisa de uma 2ª variante
   mais clara pra uso em texto (mantendo o atual só pra elementos verdadeiramente
   decorativos/terciários).
2. **[CONFIRMADO, medido] `borderRadius` sem hierarquia** — no Home real: 13px, 14px,
   20px coexistindo em cards do mesmo nível visual (grid 2×2 + card de resumo). Bate
   com o "pendente" já documentado no CLAUDE.md (~20 valores de raio fazendo o mesmo
   papel).
3. Nav inferior: `position:absolute` dentro do portal `#nav-host` (`fixed`), y=795/852,
   44px de altura — dentro do padrão, sem achado aqui.
4. Botões do header do Resumo (Comport./Crescimento/CSV): 28px de altura, padding
   "6px 10px", fontSize 11px, gap 6px entre eles — consistentes entre si.

### Limitação de ambiente (não é bug do produto)

- `preview_screenshot` trava sempre (30s timeout): o app conecta no Firestore de
  PRODUÇÃO real via long-polling, que nunca fica "idle" — a ferramenta de screenshot
  espera rede parada. Contornado com `inspect`/`eval`/`snapshot`.
- Navegação por clique no carrossel (Home→Stats via nav inferior) não pôde ser

  inconclusivo com as ferramentas disponíveis). SEM evidência de bug real aqui: é uso
  diário comprovado em produção pelo William. Não entra como achado.
